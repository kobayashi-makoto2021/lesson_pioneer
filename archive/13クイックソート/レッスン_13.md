# レッスン13: クイックソート — 分割して高速に並べよう

## できるようになること

- [ ] 分割統治法（大きい問題を小さく分けて解く）を説明できる
- [ ] ピボット（基準）を使って、小さいグループと大きいグループに振り分けられる
- [ ] スタックを使って「あとでやる仕事」を管理できる
- [ ] バブルソートとクイックソートを比較回数でくらべられる
- [ ] 速いアルゴリズムはメモリをたくさん使うことがある（トレードオフ）と説明できる

## このレッスンで必要な知識

### バブルソートの弱点

前回のバブルソートを思い出そう。8個の数字を並べるのに、比較回数は35回くらいだったね。

じゃあ、**16個**だったらどうなると思う？

「2倍の32個だから、比較も2倍の70回くらいかな？」……残念、そうはならないんだ。バブルソートは16個にすると**約200回**、4倍以上に増えてしまう。100個、1000個と増えたら、とんでもない回数になってしまうね。

そこで登場するのが、今日の主役「**クイックソート**」だよ。名前のとおり、とっても速いソートなんだ。

### 分割統治法 — 分けて、それぞれをやっつける

![分割統治法](image/分割統治法.png)

クイックソートの考え方は、**分割統治法**とよばれるものだよ。

> **大きい問題は、そのままだと難しい。だったら小さく分けて、1つずつやっつけよう。**

たとえば、教室のみんなを背の順に並べるとき。16人を一度に並べるのは大変だよね。でも、

1. まず「基準より小さい人」と「基準より大きい人」の2グループに分ける
2. それぞれのグループの中で、また同じことをする
3. どんどん分けていくと、最後は1人ずつになる = もう並んでいる！

これが分割統治法。バブルソートが「となり同士をコツコツ比べる」のに対して、クイックソートは「**バサッと2つに分ける**」んだ。

### ピボット — 分けるための基準

グループを分けるには、基準になる数が必要だよ。この基準の数を「**ピボット**」というよ。

今日のプログラムでは、**その範囲のいちばん右の数**をピボットにするよ。

たとえば、こんなリストがあったとする。

`3, 9, 1, 7, 5`

いちばん右の **5** がピボットだ。これを基準に振り分けると、

- 5より小さい → `3, 1`
- 5より大きい → `9, 7`

こうなる。まん中に置いた **5** は、**もうここで場所が確定**するんだ。だって、左側は全部5より小さくて、右側は全部5より大きいんだから！

`3, 1, [5], 9, 7`

このあとは、左の `3, 1` と、右の `9, 7` を、それぞれ同じやり方で分けていけばいいね。

### 分けたあとの「仕事」はどこにメモする？ — スタックの出番

ここでちょっと困ったことが起きる。

1回分けると、**やるべき仕事が2つに増える**んだ（左側の範囲と、右側の範囲）。左側をやっている間、右側の仕事は覚えておかないといけない。しかも、その左側をまた分けると、仕事はもっと増えていく……。

この「あとでやる仕事」をためておくのに、ぴったりの道具があったよね。

そう、レッスン09でやった **スタック** だよ！

- 分けたら、新しくできた2つの範囲を**スタックに積む（push）**
- 次にやる仕事は、スタックから**取り出す（pop）**
- **スタックが空っぽになったら、全部の仕事が終わった** = ソート完了！

今日は、範囲を「左はどこから」「右はどこまで」の2つの数で表すので、スタックも**「左スタック」と「右スタック」の2本**を使うよ。

### メモリってなに？

コンピューターが計算のとちゅうで使う「作業机」のことを **メモリ** というよ。変数やリストは、このメモリの上に置かれているんだ。

- **バブルソート**が使った作業用の場所は「一時保存」の**たった1個**
- **クイックソート**は、あとでやる仕事をためる**スタック**が必要

つまりクイックソートは、**速いかわりにメモリをよぶんに使う**んだ。こういう「あちらを立てればこちらが立たず」の関係を **トレードオフ** というよ。今日はこれも確かめてみよう。

### ステップ1: 手で分けてみよう

まずはプログラムを使わずに、自分の手でやってみよう。カードを8枚配るね。

1. カードを1列に並べる
2. **いちばん右のカード**をピボットに決める（指でおさえておこう）
3. 左から順に見ていって、ピボットより小さいカードを**左のかたまり**へ寄せる
4. 全部見終わったら、ピボットのカードを**そのかたまりのすぐ右**に置く
5. これでピボットの場所は確定！ 左のかたまりと右のかたまりに分かれたね
6. 左のかたまりだけを取り出して、**もう一度1からやる**。次は右のかたまりでもやる

> **考えてみよう：** 何回か分けていくと、かたまりの中身が1枚だけになるよね。1枚だけのかたまりは、分ける必要があるかな？

### ステップ3: 生徒用プログラムを開こう

**生徒用プログラム**をダウンロードして開こう。

![生徒用プログラム全体](image/生徒用プログラム.png)

このプログラムには、**関数（定義ブロック）が4つ**用意してあるよ。

![用意してある関数](image/与える関数.png)

| 関数 | やっていること |
|---|---|
| リスト作成 | 数字リストを空にして、乱数を「リストの個数」回追加する |
| 初期化 | 変数を最初の状態に戻し、リスト作成を呼び、**スタックに最初の範囲（1 と リストの個数）を積む** |
| 数の入れ替え | 「位置A」の数と「位置B」の数を入れ替える |
| 分割 | 「左」から「右」までの範囲をピボットで振り分けて、**ピボットが確定した場所を変数「境界」に入れる** |

**注目ポイント1：「数の入れ替え」がパワーアップしている！**

レッスン12では「となり同士」しか入れ替えられなかったけど、今回は「位置A」と「位置B」で**好きな2か所**を入れ替えられるようになっているよ。中身は同じ「一時保存」の3ステップだから、読めば思い出せるはず。

**注目ポイント2：「分割」がこのプログラムの心臓部**

「分割」の中では、こんなことをしているよ。

1. ピボット ← 数字リストの「右」番目の値（いちばん右をピボットにする）
2. 境界 ← 左 - 1（ここまでが「小さいグループ」という目印）
3. 「左」から「右 - 1」まで、1つずつ見ていく
   - 比較回数を1ふやす
   - もし、その数がピボットより小さいなら → 境界を1すすめて、その場所と入れ替える
4. 最後に、ピボットを「境界 + 1」の場所へ入れ替える
5. 境界を1すすめる ← **ここがピボットの確定した場所！**

旗のスクリプトは「初期化 → 2秒待つ」で止まっているね。**この続きを作るのが今日のミッション**だよ！

### ステップ4: メインのループを作ろう

作るのは、**スタックから仕事を取り出してくりかえす**部分だよ。フローチャートを見ながら組み立てよう。

![クイックソートのフローチャート](image/クイックソート_フローチャート.png)

流れはこうだよ。

```
左スタックの長さ = 0 になるまで、くりかえす
  ┃
  ┣ 右 ← 右スタックの最後の値を取り出して、そこを削除する（pop）
  ┣ 左 ← 左スタックの最後の値を取り出して、そこを削除する（pop）
  ┃
  ┗ もし 左 < 右 なら
      ┣ 分割                          ← 関数を呼ぶだけ！
      ┣ 左スタックに 左 を追加／右スタックに 境界 - 1 を追加   （左半分の仕事）
      ┗ 左スタックに 境界 + 1 を追加／右スタックに 右 を追加   （右半分の仕事）
```

**ヒント**

- pop は2ステップだよ。「**値を取り出す**（○番目）」→「**その場所を削除する**」。順番を逆にしないでね（レッスン09を思い出そう）
- 「左スタックの長さ」番目 が、スタックのいちばん上（Top）だよ
- 「もし 左 < 右 なら」がないと、**中身が1個以下のかたまりまで分けようとして止まらなくなる**よ
- 最後の「終わるまで Win の音を鳴らす」は、画面に置いてあるブロックをつなぐだけ

> **考えてみよう：** 「もし 左 < 右 なら」が成り立たないのは、どんなときかな？（ヒント：かたまりの中のカードは何枚？）

### ステップ5: 動かしてチェックしよう

完成したら旗を押して、正解プログラムと同じ動きになるか確かめよう。

- [ ] 数字リストが**小さい順**に並び替わった？
- [ ] 並び終わったら **Win の音**が鳴って止まった？
- [ ] 左スタック・右スタックは、最後に**空っぽ**になった？

**うまく動かないときは…**

- 止まらない → 「もし 左 < 右 なら」を入れ忘れていないかな？
- リストの数字が減った・増えた → pop の「取り出す」と「削除する」の順番が逆かも
- 左と右がごちゃまぜになる → 左スタックには左、右スタックには右。ペアがずれていないかな？
- 一部だけ並ばない → push している範囲は「左 〜 境界-1」と「境界+1 〜 右」になっている？

答え合わせは正解プログラムと見比べよう。

![プログラム本体（完成形）](image/プログラム本体_完成.png)

### ステップ6: バブルソートと速さくらべ！

いよいよ本番。**同じ16個**のデータで、2つのソートの比較回数をくらべるよ。

**バブルソートを16個にする方法**

レッスン12のプログラムを開いて、「初期化」関数の中の「**リストの個数 を 8 にする**」を「**16 にする**」に書き換えよう。それから旗を押して、比較回数をメモしてね。

**結果を書きこもう**

| ソート | 8個の比較回数 | 16個の比較回数 | 作業に使ったメモリ |
|---|---|---|---|
| バブルソート | （レッスン12の記録） | | 一時保存 1個 |
| クイックソート | | | 左スタック・右スタック |

> **考えてみよう：** 8個のときの差と、16個のときの差。どちらのほうが大きく開いた？ もし1000個だったら、どうなると思う？

**メモリもくらべてみよう**

プログラムを動かしている途中で、左スタックにいくつの数字が入っているか見てみよう。バブルソートが使った「一時保存」は1個だけだったね。

クイックソートは速いけれど、そのぶん**スタックというメモを持つ場所**が必要なんだ。これが**トレードオフ**だよ。

## まとめ

- 大きい問題を小さく分けて解く考え方を**分割統治法**という
- **クイックソート**は、**ピボット**（基準）より小さいグループと大きいグループに分けるソート。分けた時点で**ピボットの場所は確定**する
- 分けてできた「あとでやる仕事」は**スタック**にためる。スタックが空になったらソート完了
- クイックソートはバブルソートよりずっと比較回数が少ない。しかも**データが増えるほど差が広がる**
- 速いアルゴリズムは、そのぶんメモリをよぶんに使うことがある。これを**トレードオフ**という
- 次のレッスンからは、いよいよ**自由制作**！ 今まで学んだ概念を使って、自分のゲームを作ろう

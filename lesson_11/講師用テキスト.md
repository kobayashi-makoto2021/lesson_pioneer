# 講師用テキスト — レッスン11: シャッフル — IDを使ってデータの順番を変えよう

## 注意点

- **解答プログラムは2本**：`解答プログラム/11シャッフル_数字だけ.sb3`（ステップ1〜3）と `解答プログラム/11シャッフル_都道府県.sb3`（ステップ4）。どちらも**ボタンスプライト（Button2）**にスクリプトが書いてある（ステージではない）。
- **生徒用プログラムも2本**：`lesson_11/11シャッフル_数字だけ_生徒用.sb3` と `lesson_11/11シャッフル_都道府県_生徒用.sb3`。生徒がダウンロードできる場所に置いておく。
- **数字だけ版の生徒用プログラムは白紙**：緑の旗・このスプライトが押されたとき、どちらのスクリプトもコメント（付箋）だけで、ブロックは何も入っていない。フローチャートを見て**ゼロから**組み立てさせる。
- **都道府県版の生徒用プログラムは一部完成済み**：緑の旗のスクリプトと、対応表を作る関数「都道府県ID」はすでに完成している。生徒が作るのは「このスプライトが押されたとき」のスクリプトだけ。
- **変数「リストの長さ」は初期値を設定するブロックがない**。旗を押す前に、変数モニターなどで**手動で 10 を入力**させる。0のままだとくり返しが1回も動かず「何も起きない」ように見える。
- このレッスンの概念的な核は「**乱数の追加だけでは重複が出る → くじ引き方式（取り出して戻さない）で重複なしのランダムを作る**」。今回はさらに「**ID → 対応表で別のデータを引く**」という、辞書・データベースの考え方の入り口も扱う。
- 「1秒待つ」は観察用。取り除くと一瞬で終わることも体験させる。
- 次回のレッスン12（バブルソート）は「バラバラのリストを並べ直す」学習。「今日はぐちゃぐちゃにする側、次回は直す側」という予告で締めると接続がよい。

## 授業の進め方

### ① 導入 — シャッフルってなに？

![シャッフルってなに？](image/ChatGPT%20Image%202026年7月17日%2013_25_04.png)

トランプを実際に持って行ってシャッフルして見せるとよい。「シャッフル再生」「ビンゴの抽選機」など、生徒の身近な例を挙げさせる。

次に「1から10までの乱数を10回リストに追加すれば、ランダムなリストになるんじゃない？」と**わざと間違った方法を提案**する。実際にその場で組んで見せると、同じ数が2回出る・出ない数があるのが一目でわかる（`3, 7, 3, 1, 9, …` のような結果になる）。

「ビンゴで同じ番号が2回出たら?」と問いかけ、**全部の数が1回ずつ出るランダム**が必要だと確認する。

### ② くじ引き方式の説明

実物のくじ（紙を折ったもの10枚程度）か、ホワイトボードで説明する。

1. 箱からランダムに1枚引く
2. 引いたくじを机に並べる（シャッフル後のリスト）
3. **引いたくじは箱に戻さない**（シャッフル前のリストから削除）
4. 箱が空になるまでくりかえす

「戻さないから、同じくじは二度と出ない」——この1点が伝われば十分。

### ③ ループ変数の説明

![ループ変数ってなに？](image/ChatGPT%20Image%202026年7月17日%2013_35_27.png)

「○回くり返す」ブロックには、今何回目かを取り出す機能がない。だから自分で変数を用意して1ずつ増やす、という発想を確認する。「くりかえし」ではなく「ループ変数」という呼び方をこのレッスンから使うので、用語をそろえておく。

### ④ フローチャートの読み方

![フローチャートの見方](image/ChatGPT%20Image%202026年7月17日%2013_25_28.png)

図形の意味（角丸＝開始・終了、四角＝処理、ひし形＝条件分岐、矢印＝進む順番）を確認してから、今日のフローチャートを配布・投影する。

![シャッフルプログラムのフローチャート](image/シャッフルプログラム_フローチャート.png)

矢印を指でたどりながら全体の流れを一度読む。「①緑の旗が押されたとき＝リストを1〜10で埋める準備」「②このスプライトが押されたとき＝くじ引き方式でシャッフル」の2つのスクリプトに分かれていることを確認する。

### ⑤ ステップ1〜2: フローチャートからプログラムを作る（数字だけ版）

生徒用プログラム（数字だけ版）をダウンロードさせる。開いた直後は下の状態（コメントのみ）。

![生徒用プログラムの最初の状態](image/Screenshot%20from%202026-07-17%2013-42-11.png)

制作前に、変数「リストの長さ」に **10** を入れさせる（注意点を参照）。

作る順番の目安：

1. リスト2つ・変数3つをすべて作る
2. 「緑の旗が押されたとき」＝フローチャート左側（リストを空にする → ループ変数を0にする → 1〜10を作る）
3. 「このスプライトが押されたとき」＝フローチャート右側（乱数で位置を選ぶ → 追加 → 削除 → 待つ）

「考えてみよう」の答え：

- 「1ずつ変える」と「追加する」の順番を逆にすると 0〜9 になる（まだ変数が変わっていない値を追加してしまうため）
- 乱数の上限を「リストの長さ」ではなく「シャッフル前のリストの長さ」にする理由：取り出すたびにリストが短くなるので、固定の10のままだと存在しない番目を選んでしまう回がある

### ⑥ ステップ3: 動かして観察

![実行結果の例](image/Screenshot%20from%202026-07-17%2013-12-42.png)

- シャッフル前のリストが1つずつ短くなる
- シャッフル後のリストに重複が出ない
- 最後にシャッフル前のリストが空になる

ここまでで数字版は完成。「次はこの仕組みを使って、数字の代わりに都道府県名を表示してみよう」とステップ4へつなげる。

### ⑦ ステップ4: 都道府県IDにチャレンジ

都道府県版の生徒用プログラムに切り替えさせる。緑の旗のスクリプトと「都道府県ID」関数（対応表を作る）はすでに完成しているので、まずその中身を確認させる。

![都道府県版：緑の旗のスクリプト](image/Screenshot%20from%202026-07-17%2013-41-13.png)

生徒が直すのは「このスプライトが押されたとき」だけ。**IDと値を混同しないこと**がこのステップの山場。

- 「シャッフル前のリスト」の「何番目を取り出す？」番目 → これは**都道府県ID**（1, 2, 3…という数）
- そのIDを使って「対応表」の**そのID番目**を見る → これでやっと都道府県名が手に入る

正しい組み方は、Scratchのブロックで見ると**入れ子**になる。

```
対応表 の (シャッフル前のリスト の 何番目を取り出す？ 番目) 番目
```

「何番目を取り出す？」を対応表に直接使ってしまう（`対応表 の 何番目を取り出す？ 番目`）のがこのステップで一番多い間違い。これだと**ランダムな位置**をそのままIDとして対応表を引いてしまうため、同じ都道府県が何度も出たり、出ない県ができたりする。「対応表を引くときの番号は、シャッフル前のリストから取り出したIDでなければいけない」と繰り返し伝える。

完成したら `解答プログラム/11シャッフル_都道府県.sb3` と見比べさせる。

### ⑧ ステップ5〜まとめ

自分の対応表づくりは自由制作に近いので、時間が余ったクラス向け。全員必須にしなくてよい。

まとめでは「今日はリストをぐちゃぐちゃにした。次回はぐちゃぐちゃのリストを**並べ直す**（ソート）」と予告して締める。

## よくあるつまずきポイント

**「追加」と「削除」の順番が逆**

先に削除すると、追加しようとした値はもう存在しない（後ろの値がつまって別の値になっている）。「くじを箱に戻さない、の前に、まず机に並べる」と手順で覚えさせる。

**乱数の上限を「リストの長さ」に固定してしまう**

途中から存在しない番目を参照して、シャッフル後のリストに**空白**が混ざる。動きはするがリストがおかしくなる、という気づきにくいバグなので、症状（空白が入る・シャッフル前のリストに数字が残る）から逆算させるとデバッグの練習になる。

**「何番目」（位置）と「ID・値」の混同**

このレッスン全体の核心。ホワイトボードにリストの絵を描き、位置番号と中身を分けて書いて確認する。都道府県版でこの混同がそのままバグになる（上記⑦参照）。

**変数「リストの長さ」を設定していない**

0のままだとループが0回で何も起きない。「動かない」と言われたらまず変数モニターで確認させる。

**旗を押し直さずにシャッフルボタンを連打する**

シャッフル前のリストが空のままシャッフルが走り、空白が追加される。「もう一度シャッフルしたいときは、旗から押し直す」と伝える。

## 補足説明

**「乱数追加」と「シャッフル」の違い**

- 乱数を10回追加：重複あり・欠けあり。「サイコロを10回振る」イメージ
- シャッフル：同じメンバーで**順番だけ**が変わる。「トランプをまぜる」イメージ

用途が違うだけでどちらも正しいランダムの使い方。レッスン12のバブルソートでは「乱数追加」方式（リスト作成関数）でデータを作るので、両方式を経験することになる。

**この方式の正体（講師向け）**

「ランダムに選んで取り出す」方式は、シャッフルアルゴリズムとして正しく、すべての並び順が等しい確率で出る。プロのプログラムで使われるフィッシャー–イェーツ法（リスト内で入れ替えていく方式）の考え方の元になっている。生徒に伝える必要はないが、「ちゃんとしたアルゴリズムなんだよ」と言える背景として。

**ID・対応表という考え方（講師向け）**

「番号をつけて、別の表からデータを引く」のは、データベースの主キー・外部キーの考え方そのもの。生徒にその言葉を教える必要はないが、「都道府県名を直接シャッフルするのではなく、IDをシャッフルしてから対応表で引く」という設計は、実際のシステムでもよく使われる方法だと知っておくと説明に厚みが出る（例：ゲームのアイテムIDとアイテム名の対応表）。

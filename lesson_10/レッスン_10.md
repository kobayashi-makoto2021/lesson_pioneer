# レッスン10: 線にピタッと止まれ！ — 探索アルゴリズム

## できるようになること

- [ ] 線形探索と二分探索の違いを説明できる
- [ ] 毎回「真ん中」を試すと探す範囲が半分になる理由がわかる
- [ ] 「小さい」「大きい」ボタンで最小値・最大値を更新するプログラムを作れる

## このレッスンで必要な知識

### 今日のお題

![黒い線でピタッと止まれ！](image/ChatGPT%20Image%202026年7月1日%2012_01_30.png)

テープのゴールラインにtoioをピッタリ止めたい。でも…

- パワー50 → 届かなかった
- パワー100 → 行き過ぎた

**どうすれば、少ない回数でピッタリの場所を見つけられるかな？**

### 線形探索ってなに？

![線形探索ってなに？](image/ChatGPT%20Image%202026年7月1日%2015_47_39.png)

データを「順番に、1つずつ」見ていく探し方だよ。レッスン04・05でやった「全てのマスを1つずつ調べる」全探索も、線形探索の仲間なんだ！

### 線形探索は、賢くない方法！

![線形探索は、賢くない方法！](image/ChatGPT%20Image%202026年7月1日%2015_47_34.png)

1〜10の中から「8」を探すと、線形探索では8回かかる。でも二分探索なら2回で見つかるんだ！

---

### 真ん中を試してみよう！

![真ん中を試してみよう！](image/ChatGPT%20Image%202026年7月1日%2012_02_15.png)

パワー50では足りなかった。パワー100では行き過ぎた。だから正解は50〜100のどこかにあるよね。

→ だったら**真ん中の75**を試してみよう！

なぜ真ん中を試すの？  
75が「大きい」か「小さい」かがわかると、次に探す範囲が**半分**になるからだよ！

### 半分ずつせまくしていく！

![半分ずつせまくしていく！](image/ChatGPT%20Image%202026年7月1日%2012_02_23.png)

毎回「真ん中を試す → 半分に絞る」を繰り返すと、**たった5回**で正解にたどり着けるんだ！

これを「**二分探索**（にぶんたんさく）」というよ。

### 中間値の計算のしかた

![二分探索でいちばん大事なこと！](image/ChatGPT%20Image%202026年7月1日%2015_48_02.png)

中間値は **（最大値 + 最小値）÷ 2** で計算するよ。小数になった場合は切り捨てて整数にしてね（例：5.5 → 5）。

### ステップ1：手動チャレンジ — 自分でパワーを入力してみよう

先生がスタートラインとゴールラインをテープで引くよ。toioをスタートに置いて、**自分でパワーを入力**しながらゴールに止めてみよう！

1. 「前に進む」ブロックにパワーを入力して旗を押そう
2. どのくらいずれたか見て、次の数を考えよう
3. 何回でゴールにピッタリ止められたか数えておこう

> **チャレンジ：** 1ずつ増やして試すのと、毎回「真ん中」を試すのと、どちらが少ない回数で見つかったかな？

### ステップ2：二分探索プログラムをゼロから作ろう

> ⚠️ **サンプルプログラムはまだ開かないでね！** このステップは自分の力でゼロから作るチャレンジだよ。サンプルを見るのはステップ4まで待ってね。

「毎回、真ん中を試す」二分探索のプログラムをゼロから作ってみよう！

#### 変数を用意しよう

まず変数を全部作ってね。

| 変数名 | 何を表す？ | 最初の値 |
|---|---|---|
| 最大値 | 探す範囲の一番大きい数 | 100 |
| 最小値 | 探す範囲の一番小さい数 | 0 |
| 中間値 | 今回試す数 = （最小値 + 最大値）÷ 2 | 0 |
| きょり | toioが進む距離 = 0.1 × 中間値 | 0 |
| 回数 | 何回試したか | 0 |
| フラグ_回答待ち | ボタンが押されるのを待つフラグ | 0 |
| フラグ_位置を戻す | toioがスタートに戻るのを待つフラグ | 0 |

#### スプライトを確認しよう

3つのボタンスプライトを使うよ。

| スプライト | 押すとき |
|---|---|
| ぴったり（Button4） | メインのプログラムをここに書く |
| 小さい（Button3） | toioが届かなかったとき |
| 大きい（Button2） | toioが行き過ぎたとき |

#### プログラムを作ろう

**① 初期化ブロックを作る**

旗を押したとき、最初に「初期化」ブロックを呼び出すようにしよう。初期化ブロックの中で、すべての変数を初期値に戻してね。

**② ぴったりスプライトのメインループ**

ずっと繰り返す中に、次の順番でブロックを並べよう。

```
① 中間値 を （最小値 + 最大値）/ 2 にする
② きょり を 0.1 × 中間値 にする
③ toioを前に速さ30秒できょり移動かす
④ 「大きかったですか？ちいさかったですか？」と言う
⑤ フラグ_回答待ち を 1 にする
⑥ フラグ_回答待ち = 0 になるまで待つ
⑦ toioをスタートに戻す（クリックしてスタートと言う → 位置を戻す待ち）
⑧ 回数 を 1 ずつ増やす
```

**③ 小さいボタン（届かなかった！）**

「きょりが小さい」＝ toioが届かなかった ＝ 正解はもっと大きい数のはず！

→ **最小値** を 中間値 に更新しよう（下限を引き上げる）。

![小さいボタン](image/Screenshot%20from%202026-07-01%2014-51-56.png)

> **ポイント：** `フラグ_回答待ち が 1 のとき だけ` 反応するようにしてね。最後に `フラグ_回答待ち を 0 にする` を忘れずに！

**④ 大きいボタン（行き過ぎた！）**

「きょりが大きい」＝ toioが行き過ぎた ＝ 正解はもっと小さい数のはず！

→ **最大値** を 中間値 に更新しよう（上限を引き下げる）。

![大きいボタン](image/Screenshot%20from%202026-07-01%2014-52-03.png)

**⑤ ぴったりボタン（正解！）**

Win音を鳴らして、すべてを止めよう。

## まとめ

- **線形探索**は1から順番に試す方法。どんな順番のリストでも使えるけど、遅い
- **二分探索**は毎回、探す範囲の**真ん中**を試す方法。100個の中からたった約7回で見つかる！
- ポイントは「真ん中を試して、大きいか小さいかで次の範囲を決める」こと
- 今日のプログラムでは、ボタンを押すたびに**最小値か最大値**が更新されて、範囲がどんどん縮まっていくんだ

# 講師用テキスト — レッスン10: 線にピタッと止まれ！ — 探索アルゴリズム

## 注意点

- テープは黒色のビニールテープを使い、スタートラインとゴールラインを平行に貼る。toio が直進できる距離（パワー0〜100 の範囲で調整可能な距離）にゴールを設定する。
- toio の移動距離はパワー値と厳密には比例しないため、「ピッタリ」は完全一致ではなく「線の上または線をわずかに超えた位置」を合格とする基準を事前に決めておく。
- サンプルプログラムの `きょり = 0.1 × 中間値` は実機での試行によって調整した係数。生徒がゼロから作る場合は同じ係数を使わせる。
- フラグによるループ制御（フラグ_回答待ち）はレッスン02で学習済みのパターン。「ボタンが押されるまで待つ」という部分でこの概念が再登場することを伝える。

## 授業の進め方

### ① テープ貼り + 手動チャレンジ → スライド1

まず生徒と一緒にテープを貼り、toio を手動操作でゴールに止めようとする体験をさせる。一人が操作し、クラスで「パワーいくつがいい？」と予測させながら進める。

> 例：パワー50 → 届かない。パワー100 → 行き過ぎる。

体験後にスライドを見せ、「これが今日解決したい問題」だと確認する。

### ③ プログラム制作（ゼロから作る）

変数・ブロックの構成を黒板に書いてから作業開始させると迷いが減る。

**使う変数（最初に全部作らせる）**

| 変数 | 役割 | 初期値 |
|---|---|---|
| 最大値 | 探す範囲の上限 | 100 |
| 最小値 | 探す範囲の下限 | 0 |
| 中間値 | 今回試すパワー = (最小値 + 最大値) / 2 | 0 |
| きょり | toio が進む距離 = 0.1 × 中間値 | 0 |
| 回数 | 試した回数 | 0 |
| フラグ_回答待ち | ボタン入力を待つフラグ | 0 |
| フラグ_位置を戻す | toioがスタートに戻るのを待つフラグ | 0 |

**作る順番の目安**

1. 初期化ブロック（全変数をリセット）
2. ぴったりスプライトのメインループ
   - 中間値 ← (最小値 + 最大値) / 2
   - きょり ← 0.1 × 中間値
   - toio を前に進める（速さ30、秒できょり）
   - 「大きかったですか？ちいさかったですか？」と言う
   - フラグ_回答待ち を 1 にする → 0 になるまで待つ
   - toio をスタートに戻す
   - 回数 を 1 ずつ増やす
3. 小さいボタン（届かなかった）のスクリプト
4. 大きいボタン（行き過ぎた）のスクリプト
5. ぴったりボタン（正解）のスクリプト

## よくあるつまずきポイント

**「小さい」「大きい」ボタンの意味を逆に押す**

ボタンが示すのは「toioの動き」についての評価であって「目標の値」ではない。

- 小さい = きょりが足りなかった（toio が届かなかった）→ 最小値を中間値に更新
- 大きい = きょりが行き過ぎた（toio が通り過ぎた）→ 最大値を中間値に更新

「toio の視点で、動きが少なすぎた→小さい、多すぎた→大きい」と言い換えると覚えやすい。

**最小値・最大値を更新するブロックを逆に書く**

- 小さいボタン（足りなかった）: `最小値 ← 中間値`（下限を上げる）
- 大きいボタン（行き過ぎた）: `最大値 ← 中間値`（上限を下げる）

誤って逆方向に更新すると探索範囲が広がり続けてバグになる。

**フラグ_回答待ちのリセットを忘れる**

ボタンを押したあと、`フラグ_回答待ち を 0 にする` を入れないとメインループが止まったまま再開しない。

**手動チャレンジでパワーと距離の対応に戸惑う**

サンプルプログラムでは「パワー100 = 速さ30で10秒（0.1×100）進む」という換算をしている。生徒が混乱したら「100が最大、0が最小、そこから真ん中を計算するだけ」とシンプルに伝える。

## 補足説明

**なぜ最大100回が約7回になるのか**

100 → 50 → 25 → 13 → 7 → 4 → 2 → 1 と半分になっていくので、2の何乗が100を超えるかを考えると 2⁷ = 128 ≥ 100 → 約7回。「半分にし続ける」の強力さを実感させる。

**フラグによるループ制御（レッスン02との接続）**

```
フラグ_回答待ち を 1 にする
フラグ_回答待ち = 0 まで待つ
```

この「フラグを立てて、別のスプライトがフラグを下ろすまで待つ」パターンはレッスン02のループアンドフラグと同じ構造。「ボタンが押されるまで何もしない」という待機の実装方法として定着させる。

**探索アルゴリズムの全体像（まとめ時に使う）**

| レッスン | 探索方法 | 特徴 |
|---|---|---|
| レッスン03 | ランダム探索 | でたらめに試す、終わりが読めない |
| レッスン05 | 全探索 | もれなく全部試す、確実だが遅い |
| （概念のみ） | 線形探索 | 順番に試す、リストがバラバラでも使える |
| レッスン10 | 二分探索 | 毎回半分に絞る、**ソート済み**の場合に最速 |

「これまで習った探索が全部つながる」という視点で締めくくると印象に残りやすい。

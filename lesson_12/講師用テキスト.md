# 講師用テキスト — レッスン12: 自由制作① — 企画・設計して作りはじめよう

## 注意点

- **レッスン12〜15の4回で1つの作品を完成させる**。今日は企画・設計と制作開始。カリキュラム改訂により、以前この位置にあったソート（バブルソート・クイックソート）はフェーズ2（Python・レッスン28〜29）へ移動した。
- **レッスン07でも企画を行っている**。今回はレッスン08〜11で習った概念（キュー・スタック・二分探索・シャッフル）が加わった状態での再企画。レッスン07の企画シートを持っている生徒には持参させ、**ふくらませる／作り直す のどちらでもよい**と伝える。
- **この回の最大の役割はスコープ調整**。生徒は必ず大きく作りたがる。「小さく作って、余ったら足す」を最初と最後の2回言う。
- **設計図（ステップ3・4）を必ず紙に書かせる**。書かずに制作へ進んだ生徒は、レッスン13以降で確実に手が止まる。
- 制作時間は今日25分・レッスン13が45分・レッスン14が30分程度。**実質2時間弱**という数字を生徒にも共有すると、スコープ感が伝わりやすい。
- 印刷物として、ステップ1〜4の記入シート（1〜2枚）を用意しておくとスムーズ。
- 使う画像は特にない。`image/` は空のままでよい。
- **並び替え（ソート）を使いたい生徒**が出た場合は、`archive/12バブルソート/12バブルソート_正解.sb3` を参考資料として渡してよい。ただし理解までは求めず「部品として使う」扱いにとどめる。

## 授業の進め方

### ① 4回の流れを共有する（5分）

まずゴールを見せる。

| 回 | やること |
|---|---|
| 12（今日） | 企画・設計 → 制作スタート |
| 13 | 制作 |
| 14 | 遊んでもらって直す・仕上げ |
| 15 | 発表 |

「**レッスン15で全員が発表する**」ことを最初に明言しておくと、締め切り意識が生まれてスコープが自然に締まる。

### ② 概念カタログを一覧で確認する（7分）

レッスン01〜11の14概念を一覧で見せ、**名前を聞いて内容が浮かぶか**をざっと確認する。全部を復習し直す必要はない。忘れている概念があれば、該当レッスンのテキストを見返させる。

「3つ以上使う」という条件は、**概念を思い出すきっかけ**として設けている。無理に難しい概念を入れさせる必要はない。

### ③ ステップ1〜2: アイデアと概念選び（15分）

アイデアが出ない生徒への声かけの引き出し。

- 「レッスン07の企画、今なら作れそう？」
- 「これまで作ったプログラムで、一番面白かったのはどれ？ それを改造するなら？」
- 「好きなゲームの、どの場面をtoioでやってみたい？」
- 「toio 2台なら、どんな役割にする？」（追いかけっこ・かくれんぼ・協力ゲーム）

**概念選びで必ず確認すること**：「どこで使う？」が書けているか。ここが空欄のまま制作に入ると、概念を使わないまま完成してしまう。1人ずつ口頭で答えさせるのが確実。

### ④ ステップ3〜4: 設計図とToDoリスト（15分）

**画面の絵**は、上手さは不問。スプライト・変数モニター・toioの動きが描かれていればよい。

**ToDoリスト（作る順番）はこの回の核心。** 講師が一人ずつ見て、以下を確認する。

- **1番目が「作品の心臓部」になっているか**（見た目や音が1番目になっていたら並べ替えさせる）
- 1項目が大きすぎないか（「ゲームを作る」のような粒度は分割させる）
- 4〜7個に収まっているか。8個以上なら削るものを決めさせる
- 「削ってもいい番号」に印がついているか

ここで**スコープを一緒に削る**のが講師の一番の仕事。「これは今回はナシにして、余ったら足そう」と具体的に線を引く。

### ⑤ ステップ5: 制作スタート（15分）

ToDoの1番から着手させる。この時間は「軌道に乗せる」ことが目的なので、完成度は問わない。

**「少し作ったら、すぐ動かす」を徹底させる。** 10個ブロックを並べてから初めて実行する生徒には、その場で「今すぐ1回動かしてみて」と割り込む。

### ⑥ 保存と次回の1行（3分）

- ファイル名は命名規則にそって保存（`日付名前番号.sb3`）
- ToDoリストにチェック
- **「次回いちばん最初にやること」を1行書かせる**。これがあるとレッスン13の立ち上がりが劇的に速くなる

## よくあるつまずきポイント

**やりたいことが大きすぎる**

最頻出。「ステージ5個」「キャラ10種類」などが出たら、**その場で数字を減らす**。「まずステージ1個を完成させて、時間が余ったら2個目」と、削るのではなく**後回しにする**言い方をすると納得しやすい。

**アイデアが全く出ない**

白紙のまま10分が過ぎたら、講師から選択肢を3つ提示して選ばせてよい。「宝探しの改造」「二分探索AIの改造」「シャッフルを使ったクイズ」など、既存教材の改造を勧めるのが確実。ゼロから考えることはこのレッスンの目的ではない。

**概念を「使う」と書いたが、どこで使うか言えない**

企画がまだ具体化していないサイン。「点数はどうやって数える？」→ カウンター変数、「敵はどこに出る？」→ 乱数とXY座標、のように、**作品の中身を質問して概念に結びつける**方向で誘導する。

**設計図を書かずに作りはじめる**

早く作りたい気持ちは尊重しつつ、「設計図は5分で終わるから先に書こう」と止める。ここを飛ばした生徒がレッスン13〜14で最も苦労する。

**難しい概念を無理に入れようとする**

「二分探索を使いたいけど、探すものがない」など。**作品に必要ない概念は外させる**。3つの条件は満たす必要があるが、無理に高度なものを選ぶ必要はない。

**ToDoの1番目が「背景を描く」になっている**

見た目から入りたがるのは自然だが、時間切れの原因になる。「動く仕組みが先、飾りはあと」と並べ替えさせる。

## 時間配分の目安

| 内容 | 目安 |
|---|---|
| ① 4回の流れの共有 | 5分 |
| ② 概念カタログの確認 | 7分 |
| ③ ステップ1〜2: アイデア・概念選び | 15分 |
| ④ ステップ3〜4: 設計図・ToDoリスト（講師チェック含む） | 15分 |
| ⑤ ステップ5: 制作スタート | 15分 |
| ⑥ 保存・次回の1行 | 3分 |

③④が早く終わった生徒は、そのまま⑤の制作へ進めてよい。逆に④で詰まっている生徒は、⑤を削ってでも設計図を完成させることを優先する。

## 補足説明

**レッスン07との違い**

| | レッスン07 | レッスン12 |
|---|---|---|
| 使える概念 | 9個（L01〜06） | 14個（L01〜11） |
| 選ぶ数 | 2つ以上 | 3つ以上 |
| 目的 | 復習と企画の練習 | **実際に作り切るための設計** |
| 設計図 | なし | 画面の絵＋ToDoリスト |

レッスン07は「企画の練習」、レッスン12は「本番の設計」という位置づけ。同じことを2回やるのではなく、**道具が増えた状態でスコープと手順まで詰める**のが今回。

**スコープ調整の具体的な目安（講師向け）**

60分×3回強＝実質2時間弱。この時間で小学生が作れる量は、経験的に以下くらい。

- スプライト2〜4個
- スクリプトの総ブロック数 40〜80個程度
- 新しく作る仕組みは1〜2個（残りは既存プログラムの流用）

「既存プログラムの流用は大歓迎」と明言してよい。宝探し・シャッフル・二分探索AIのsb3を開いて、必要なスクリプトをコピーして使わせると、完成率が大きく上がる。

**ToDoリストという習慣（講師向け）**

作業を小さく分けて順番に並べる、終わったらチェックする、というのは、プログラミングに限らず一生使える技術。「プロもやっている」と伝えることで、面倒な作業ではなく**かっこいい作業**として受け取ってもらう。レッスン13以降も毎回このリストを起点に授業を始める。

**フェーズ1の締めくくりとして**

レッスン15の発表でフェーズ1（toio Do）が終わり、レッスン16からPythonに移る。この4回は「ビジュアルプログラミングでできることの集大成」という位置づけになる。生徒にもレッスン15で伝えるが、講師は最初からこの見通しを持って進行する。

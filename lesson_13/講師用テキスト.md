# 講師用テキスト — レッスン13: クイックソート — 分割して高速に並べよう

## 注意点

- **事前準備**: `13クイックソート_正解.sb3` と `13クイックソート_生徒用.sb3` の2つを、生徒がダウンロードできる場所に置いておく（レッスン12と同じ配置ルール）。カード8枚（数字を書いた紙でもトランプでもよい）も人数分用意する。
- **レッスン12の比較回数の記録**を必ず持参させる。ステップ6の速さくらべで使う。忘れた生徒がいる場合は、レッスン12のプログラムを開いて8個で1回測り直させる。
- **再帰は使わない**。ブロック定義が自分自身を呼ぶ再帰版は小4〜中1には抽象度が高すぎるため、**未処理の範囲をスタックに積む方式**で実装している。レッスン09のスタック（push/pop）がここで回収される設計。
- **生徒用プログラムに入っているもの**: 関数4つ（リスト作成／初期化／数の入れ替え／分割）と、旗 →「初期化」→「2秒待つ」までのスクリプト、および「終わるまで Win の音を鳴らす」ブロック（未接続）。**生徒が作るのはメインのループ部分だけ**。レッスン12と同じ設計思想。
- **「数の入れ替え」はレッスン12から仕様が変わっている**。レッスン12は「いまの位置」と「その右どなり」しか入れ替えられなかったが、今回は変数「位置A」「位置B」で任意の2か所を入れ替える。中身の一時保存3ステップは同じ。この違いは③で必ず触れる。
- **「分割」関数がこのレッスンの心臓部**だが、生徒には組ませない。中身の読解までを全体で行う。
- **リストの個数は16、数値の範囲は50**で初期化している。16個にするのは、8個ではバブルとクイックの差が小さく（35回 vs 約20回）「圧倒的に速い」実感が出ないため。数値の範囲を50にしているのは重複を減らすため。
- 変数「境界」は**関数の戻り値の代わり**。Scratchのブロック定義は値を返せないので、「分割」が結果をグローバル変数「境界」に入れる形にしている。生徒には「分割が終わると、境界にピボットの場所が入っている」とだけ伝えればよい。
- レッスン14からは自由制作に入る。まとめで「今まで学んだ概念を使って自分のゲームを作る」と予告して締める。

## 授業の進め方

### ① 導入 — バブルソートの弱点

レッスン12の比較回数を数名に発表させ、ホワイトボードに並べる（8個で35回前後）。

そのうえで問いかける。「では**16個**だったら何回になると思う？」

多くの生徒は「2倍だから70回くらい」と答える。ここで**実際に測らせる**とインパクトが強い（レッスン12のプログラムの初期化関数の「リストの個数 8」を16に書き換えて実行 → 約200回）。時間がなければ数字だけ伝えてもよいが、ステップ6でどのみち測るので、ここで測ってしまい、その値をステップ6でも使う運用が効率的。

「データが2倍になると、比較回数は4倍。100個、1000個になったら？」と広げ、**もっと速いソートが必要**という動機づけをする。

### ② 分割統治法とピボット — カードで手を動かす

![分割統治法](image/分割統治法.png)

まず言葉で押さえる。

> 大きい問題は難しい。だったら小さく分けて、1つずつやっつける。これが**分割統治法**。

次に**カード8枚で人力クイックソート**をやらせる。ここは必ず手を動かさせること。

1. カードを1列に並べる
2. **いちばん右**をピボットに決める（今回のプログラムの方式に合わせる）
3. 左から順に見て、ピボットより小さいカードを左のかたまりへ寄せる
4. 最後にピボットを、そのかたまりのすぐ右へ置く
5. **ピボットの場所はここで確定**（左は全部小さい・右は全部大きいから）
6. 左のかたまり、右のかたまりで同じことをくりかえす

「一度分けたピボットは、**もう二度と動かない**」——この一点が理解の核。ホワイトボードで確定したピボットに丸をつけていくと視覚的にわかりやすい。

バブルソートとの対比も言葉にする。

| | 動き方 |
|---|---|
| バブルソート | となり同士を比べて、1マスずつじわじわ移動 |
| クイックソート | 基準で一気に2つに分ける。遠くへ一足飛びに動く |

### ③ スタックの再登場と生徒用プログラムの読み込み

![生徒用プログラム全体](image/生徒用プログラム.png)

②で「左のかたまりと右のかたまり、両方やらないといけないね。片方をやっている間、もう片方はどこに覚えておく？」と問いかける。**レッスン09のスタック**を思い出させる。

- 分けたら、新しい2つの範囲を**push**
- 次の仕事は**pop**で取り出す
- **スタックが空 = 全部の仕事が終わった**

範囲は「左」と「右」の2つの数で表すため、スタックも**左スタック・右スタックの2本**を使うことを確認する。

生徒用プログラムを開かせ、用意してある関数4つを全体で読む。

![用意してある関数](image/与える関数.png)

| 関数 | 中身 | 確認ポイント |
|---|---|---|
| リスト作成 | 数字リストを空にして、1〜「数値の範囲」の乱数を「リストの個数」回追加 | レッスン12と同じ |
| 初期化 | リストの個数=16、数値の範囲=50、比較回数=0 などをリセット → リスト作成 → **左スタックに1、右スタックに16を追加** | 最初の仕事を1つスタックに積んでいる |
| 数の入れ替え | 一時保存を使って「位置A」と「位置B」を入れ替える | レッスン12から**任意の2か所**に強化された点を必ず触れる |
| 分割 | 下記 | このレッスンの心臓部 |

**「分割」の中身は必ず全体で読む**（組ませはしない）。

1. ピボット ← 数字リストの「右」番目（いちばん右をピボットに）
2. 境界 ← 左 - 1
3. 「左」から「右 - 1」まで1つずつ見る：比較回数を1ふやす → もしピボットより小さければ、境界を1すすめてその場所と入れ替える
4. ピボットを「境界 + 1」の場所へ入れ替える
5. 境界を1すすめる ← **ピボットが確定した場所**

「境界」は「ここまでが小さいグループ」という**仕切りの位置**だと説明するとよい。②のカード操作の「左のかたまりの右端」と同じもの。

![実行後のステージ](image/実行後のステージ.png)

ゴールのイメージを持たせるため、正解プログラムを2〜3回実行させる。中のブロックは見せない。

- 数が「となりへ」ではなく「遠くへ飛ぶ」動きを観察させる
- **左スタック・右スタックのモニター**に注目させる。仕事が増えたり減ったりする様子が、そのままアルゴリズムの動きになっている
- 最後の**比較回数**をメモさせる（16個で約50回前後）

「①で測ったバブルソートの16個は約200回だったね。これが今日のゴール」と対比しておく。

### ⑤ メインのループを作る

![クイックソートのフローチャート](image/クイックソート_フローチャート.png)

フローチャートを提示し、旗スクリプトの続きを組ませる。構造はレッスン12より単純（ループは1つ）だが、**popの2ステップ**と**push時のペア**でつまずきやすい。

```
左スタックの長さ = 0 になるまで繰り返す
  右 ← 右スタックの（右スタックの長さ）番目 → その場所を削除
  左 ← 左スタックの（左スタックの長さ）番目 → その場所を削除
  もし 左 < 右 なら
    分割
    左スタックに 左 を追加／右スタックに 境界 - 1 を追加
    左スタックに 境界 + 1 を追加／右スタックに 右 を追加
```

板書しておく対応。

- 「スタックが空？」＋上に戻る矢印 → **「左スタックの長さ = 0」まで繰り返す**
- pop は「**取り出してから削除**」の2ステップ（レッスン09の復習）
- 「もし 左 < 右 なら」（戻る矢印なし） → **もし〜なら**
- push は必ず**左スタックと右スタックをペアで**

口頭でブロックの並びは教えない。詰まっている生徒には「フローチャートのどこまでできた？」と図に戻す方向で支援する。

### ⑥ 動かしてチェック・正解と比較

![プログラム本体（完成形）](image/プログラム本体_完成.png)

- 小さい順に並ぶか
- Win の音が鳴って止まるか
- **左スタック・右スタックが最後に空になっているか**（ここが一番のチェックポイント）

正解プログラムと見比べさせ、「もし 左 < 右 なら」が必要な理由（かたまりが1個以下なら分ける必要がない・入れないと無限ループになる）を全体で確認する。

### ⑦ 速さくらべとまとめ

表を配布（または板書）して記入させる。

| ソート | 8個 | 16個 | 作業メモリ |
|---|---|---|---|
| バブルソート | 約35回 | 約200回 | 一時保存 1個 |
| クイックソート | 約20回 | 約50回 | 左スタック・右スタック |

押さえること。

- 8個では約1.7倍差。16個では**約4倍差**。→ **データが増えるほど差が広がる**
- クイックソートはスタックという「メモを置く場所」が必要。バブルソートは変数1個で足りた
- 速さとメモリの**トレードオフ**。世の中のアルゴリズムはこのバランスで選ばれている

最後に「次回からは自由制作。今まで学んだ概念を組み合わせて、自分のゲームを作ろう」と予告する。

## よくあるつまずきポイント

**pop の「取り出す」と「削除する」の順番が逆**

先に削除してしまうと、取り出そうとした値がもう存在しない。レッスン09・レッスン11でも同じつまずきが出ている定番。「くじを机に並べてから、箱から消す」の順で覚えさせる。

**「もし 左 < 右 なら」を入れ忘れる**

かたまりが1個以下（左 ≧ 右）の範囲まで分割しようとして、範囲がおかしくなり**止まらなくなる**。症状が「終わらない」なので、まずここを疑わせる。カード操作の「1枚だけのかたまりは分ける必要がない」に戻して説明する。

**push するときに左スタックと右スタックがずれる**

左スタックに2つ追加したのに右スタックに1つしか追加していない、順番が入れ替わっている、など。**ペアで1つの仕事**であることを、スタックのモニターを見せながら確認する。長さが常に同じであることをチェック方法として教えるとよい。

**push する範囲をまちがえる**

「左 〜 境界」「境界 〜 右」のように境界を含めてしまうと、確定済みのピボットをもう一度処理してしまい、終わらない・または並びきらない。「**ピボットの場所（境界）はもう確定したから、次の仕事には入れない**」と、②のカードで丸をつけた確定ピボットに戻して説明する。

**「境界」が何なのかわからなくなる**

「ここまでが小さいグループ」という仕切りの位置。分割が終わった瞬間は「ピボットが確定した場所」になる。変数モニターを表示させ、分割の前後で値がどう動くか実行しながら追わせるとよい。

**「分割」の中身を自分で組もうとする**

今日組むのはメインのループだけ。関数はパレットに出ているので、呼ぶブロックの位置を見せる。

**レッスン12の比較回数を持っていない**

その場でレッスン12のプログラムを開かせ、8個で1回実行して記録させる。①で16個も測っておくと、ステップ6が短縮できる。

## 補足説明

**なぜ「いちばん右」をピボットにするのか（講師向け）**

実装が最も単純になるため（Lomuto方式）。まん中や乱数で選ぶ方式もあり、そのほうが性能は安定するが、今回は「ピボット＝いちばん右」と固定したほうが、カード操作とプログラムの対応が一対一で見えるので採用している。生徒に方式名を教える必要はない。

**比較回数の目安**

| データ数 | バブルソート | クイックソート |
|---|---|---|
| 8個 | 約21〜56回（平均35回前後） | 約15〜25回 |
| 16個 | 約150〜250回 | 約45〜60回 |
| 32個 | 約600〜1000回 | 約120〜150回 |

乱数によってばらつくので、「だいたいこのくらい」で扱う。**データを2倍にしたときの増え方**（バブルは約4倍、クイックは約2倍と少し）が本質なので、そこに注目させる。

**すでに並んでいるデータだと？（講師向け・発展）**

このピボット選びだと、すでに小さい順に並んだデータではクイックソートが最も苦手なパターンになり、比較回数がバブルソート並みに増える。時間があり、かつ興味を示す生徒がいれば「クイックソートにも苦手なデータがある」と紹介してよいが、全体には出さなくてよい。

**メモリのトレードオフ（講師向け）**

厳密にはクイックソートのスタックの深さは平均で log2(データ数) 程度（16個なら4段前後）。「16個のデータを並べるのに、4つくらいの仕事を覚えておく必要がある」という具体で伝えると実感しやすい。データが1000個になっても10段程度で済むことにも触れると、「メモリはそこまで爆発しない」という正しい感覚が持てる。

**ソート学習の位置づけ**

| レッスン | ソート | キーワード |
|---|---|---|
| 12 | バブルソート | 隣同士の比較・入れ替え、比較回数の導入 |
| 13 | クイックソート | 分割統治法、スタックの活用、計算量とメモリのトレードオフ |

レッスン14（自由制作①）ではソートは「難易度高」の参考扱い。無理に使わせる必要はないが、「並び替えが必要なゲーム（ランキング表示など）」を作りたい生徒には、この2つのプログラムを部品として流用させてよい。

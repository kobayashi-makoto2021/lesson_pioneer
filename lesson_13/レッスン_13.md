# レッスン13: 自由制作② — 作ろう

## できるようになること

- [ ] ToDoリストを見て、今日やることを自分で決められる
- [ ] 「少しずつ作って、すぐ動かす」やり方で制作を進められる

- [ ] 変数モニターやコメントを使って、プログラムの中身を確かめられる
- [ ] 予定どおりに進まないとき、やることを減らす判断ができる

### バグはあって当たり前

プログラムが思ったとおりに動かないことを **バグ** といって、直すことを **デバッグ** というよ。

大事なことを言うね。

> **バグは失敗じゃない。プログラムを作れば、必ず出る。**

プロのプログラマーも、作っている時間の半分くらいはデバッグをしているんだ。だから、うまく動かなくてもへこまなくていい。**直し方を知っているかどうか**が差になるんだよ。

### デバッグの3つの技

うまく動かないとき、やみくもにブロックを動かすと、もっとわからなくなる。順番にやろう。

**技1：どこまでは合っているか、をさがす**

「全部おかしい」ということはめったにない。たいていは**どこか1か所**から先がおかしいんだ。

- プログラムの前半だけ動かしてみる
- 途中に「1秒待つ」を入れて、どこまで進むか見る
- 途中に「〇〇と言う」を入れて、そこを通ったか確かめる

**技2：変数の中身を見る**

変数モニター（画面に変数を表示するチェックボックス）を全部オンにしよう。

「点数が増えない」なら、点数の変数が本当に増えていないのか、増えているけど表示が違うのか。**目で見れば一瞬でわかる**よ。

**技3：一度に1つだけ直す**

あやしいところを2つ同時に直すと、どっちが効いたのかわからなくなる。

> 1つ直す → 動かす → 1つ直す → 動かす

めんどうに見えて、これがいちばん速いんだ。

### 元にもどせるようにしておこう

大きく作りかえる前に、**今のファイルを別の名前で保存**しておこう。

```
0510makoto01.sb3  ← 今できているもの
0510makoto02.sb3  ← 作りかえる用
```

こうしておけば、失敗しても前の状態にもどれる。「壊れたらどうしよう」と思わずに、思いきって試せるようになるよ。

## ミッション

設計図にそって、作品を作り進めよう！

---

### ステップ1: 今日のゴールを決めよう

前回のToDoリストを開こう。

```
前回できたところ：

今日やること（ToDoの何番から何番？）：

今日のゴール（授業の終わりにどうなっていたい？）：
```

> **ポイント：** 「全部作る」ではなく「**ToDoの3番までを動くようにする**」のように、はっきり決めよう。決めた人ほど進むよ。

---

### ステップ2: 作ろう

ToDoの順番どおりに作っていこう。ルールは前回と同じだよ。

- **少し作ったら、すぐ動かす**
- できたらToDoにチェックを入れる
- 見た目・音・演出はあとまわし

**行きづまったら、この順番でためそう**

1. どこまでは合っている？（技1）
2. 変数の中身はどうなってる？（技2）
3. あやしいところを1つだけ直して、動かす（技3）
4. それでもわからなければ、**先生に聞く**

先生に聞くときは、この3つを伝えると解決が速いよ。

```
① 何をしたかった？
② どうなると思った？
③ 実際はどうなった？
```

---

### ステップ3: 中間チェック

制作の途中で、いったん手を止めて確かめよう。

- [ ] 選んだ**3つの概念**は、ちゃんと作品の中に入っている？（まだなら、どこで入れる？）
- [ ] 誰かに「これ何のプログラム？」と聞かれたら、**30秒で説明**できる？
- [ ] 今のペースで、レッスン14の終わりまでに完成しそう？

> **もし間に合わなそうなら…** 今のうちにToDoから**削るものを決めよう**。前回、削ってもいい番号に印をつけたよね。完成しないまま発表するより、小さくても完成させたほうがずっといい作品になるよ。

---

### ステップ4: 保存して、次回の準備

**今日の終わりに**

- [ ] ファイルを保存した（`日付名前番号.sb3` の形式）
- [ ] ToDoリストにチェックを入れた
- [ ] 動いていない場所があれば、メモに書いた

```
次回いちばん最初にやること：

まだ直っていないところ：
```

次回（レッスン14）は、**友だちに遊んでもらう**よ。遊んでもらえる形になるように、今日は「とりあえず最後まで動く」ところを目指そう。

## まとめ

- バグは失敗ではなく、**必ず出るもの**。デバッグのやり方を知っているかが大事
- デバッグの3つの技 —— ①どこまで合っているかさがす ②変数の中身を見る ③一度に1つだけ直す
- 大きく作りかえる前に、**別名で保存**しておくと安心して試せる
- 質問するときは「①何をしたかった ②どうなると思った ③実際どうなった」の3点セット
- 予定に間に合わないときは、**やることを減らす**のも正しい判断
- 次回は友だちに遊んでもらう。まずは最後まで動く形を目指そう
